# Настройка штаба и дашборда

## Промпт 4. Правила процесса

```text
На основе образца подготовь мой team-rules.md. Спрашивай по одному, какие стадии
идут иначе и кто подтверждает каждую точку контроля. После «Анализ готов» добавь
отдельную стадию «Анализ проверен лидом». Закрывай её по подтверждению лида.

Запиши правила переходов To do → Ongoing → Done — контроль эффекта. В Done проект
попадает после презентации, отправки результатов заказчику и загрузки проекта
в библиотеку. Отправку и загрузку фиксируй отдельными отметками с датами и ссылками.

В AGENTS.md допиши, как по карточке и файлам определить первую незакрытую стадию,
назвать следующий шаг и ответственного. Покажи оба файла до сохранения и жди «ок».
```

## Промпт 5. Карточки проектов

```text
В шаблон и карточки projects/<имя-проекта>/README.md добавь поле status со значениями
todo, ongoing или done, а также поля стадия, следующий_шаг и за_кем_шаг. Для контроля
эффекта добавь дату следующей проверки. Добавь отдельные отметки «Результаты
отправлены заказчику» и «Проект загружен в библиотеку» с датами и ссылками.

По team-rules.md проверь файлы и отметь стадии, для которых есть подтверждения.
Сохрани текущие пути к папкам проектов. Если данных не хватает, напиши, что нужно
уточнить. Покажи предложенные изменения по каждому проекту и жди «ок».
```

## Промпт 6. Дашборд

```text
Собери dashboard.html, который открывается с диска. Бери статус из шапки README.md
каждого проекта. Покажи три колонки в этом порядке: To do, Ongoing, Done — контроль
эффекта. На каждой карточке покажи имя, номер РП при наличии, стадию, следующий шаг,
за кем он и срок. Просроченные сроки выделяй. В Done покажи дату ближайшей проверки
или «Эффект зафиксирован».

Допиши в AGENTS.md: после сохранения состояния проекта обновляй projects/index.md
и пересобирай дашборд из карточек. Папки проектов оставляй на их постоянных путях.
```
